# New-mir — История проекта и переписка

Этот файл документирует историю разработки проекта **New-mir** — нейросетевого движка
генерации кода на основе сотовой (honeycomb) архитектуры памяти.

---

## Сессия 1 — Создание проекта (24 июля 2026)

### Задача
Создать нейросетевую программу для генерации кода с архитектурой из 4 слоёв,
работающую на любом Linux-железе без облаков.

### Архитектурные решения

**Слой 1 — HoneycombMemory (`core/cell_memory.py`)**
- Пул ячеек-сот с адресным пространством 2²⁵⁶ уникальных ID (SHA-256)
- LRU-вытеснение при переполнении ёмкости
- Автоматическое расширение: при заполнении 70% создаётся новый шард на 65 536 ячеек
- Экспорт/импорт состояния в JSON

**Слой 2 — QRBinaryEncoder (`core/qr_encoder.py`)**
- Кодирование любых байт в QR-матрицы (numpy)
- Каждый QR-слот идентифицируется SHA-256 хэшем
- PNG-экспорт QR-кодов для визуализации

**Слой 3 — BinaryCompressionEngine (`core/binary_engine.py`)**
- Мультиалгоритмное сжатие: LZ4, ZSTD, zlib, Delta+ZSTD
- Автовыбор лучшего алгоритма для каждого типа данных
- Бинарный формат NMC1 (New-mir Compressed v1)
- Информация хранится в машинном коде 0 и 1

**Нано-модель — NeuralCodeGen (`core/neural_core.py`)**
- Transformer-декодер реализован на чистом numpy (без PyTorch/GPU)
- Файн-тюнинг на загруженных пользователем данных
- Работает на слабом железе, нагрузка ≤ 50% CPU

**Слой 4 — FastAPI (`api/main.py`, `api/converters.py`)**
- Конвертация любых форматов: текст, PDF, DOCX, видео, аудио, код, архивы
- REST API + веб-интерфейс на `0.0.0.0:8000`

### Инфраструктура
- `Dockerfile` + `docker-compose.yml` (запуск одной командой)
- `install.sh` — автоустановка Docker и systemd-сервиса на любом Linux
- Ограничение нагрузки: `cpus: 1.0` в docker-compose (≤ 50% CPU)

## Сессия 2 — Вкладка обучения (24 июля 2026)

### Добавлено
- **Вкладка ⬡ Обучение** в веб-интерфейсе
- Полный цикл обучения через UI:
  1. Загрузка любых файлов drag-and-drop
  2. Файл → сжатие (Layer 3) → QR-слоты (Layer 2) → ячейка (Layer 1)
  3. Если текстовый/кодовый контент — дообучение нано-модели
  4. Исходный файл удаляется, обученная информация остаётся навсегда
- Автоматическое создание нового шарда при заполнении 70% ячеек
- Уведомление в UI об автоматическом расширении памяти

### Поддерживаемые форматы
`.pt .bin .npz .gguf .safetensors` (веса нейросетей), `.zip .tar.gz` (архивы),
`.py .js .go .rs .c .cpp .java` (код), `.pdf .docx .txt .md .csv .json` (документы),
`.mp4 .mp3 .wav .png .jpg` (медиа) — и любые другие.

## Сессия 4 — GPT-2 + исправление стриминга (24 июля 2026)

### Проблема
Стриминг был сломан: `list(_sync_gen())` в executor буферизовал **все** токены
прежде чем отправить первый байт. Кнопки Стоп и Продолжить не работали.

### Решение
- Создан `core/gpt2_backend.py` — GPT-2 бэкенд через HuggingFace transformers
- Стриминг переписан на `threading.Queue` мост: токены идут в браузер немедленно
- GPT-2 подключён к ChatEngine для вкладки Чат
- Нано-модель осталась для вкладки Code Gen

### Выбор модели чата
Управляется переменной окружения `NEW_MIR_CHAT_MODEL`:
| Значение | Описание |
|---|---|
| `gpt2` (умолчание) | Английский + другие языки, ~550 МБ |
| `sberbank-ai/rugpt3small` | Русский язык, ~500 МБ |
| `bigscience/bloom-560m` | 46 языков мира, ~1 ГБ |
| `gpt2-medium` | Лучший английский, ~1.5 ГБ |

## Команды запуска

```bash
# Клонировать и запустить
git clone https://github.com/mintfary-oss/New-mir.git
cd New-mir
pip install -r requirements.txt
python main.py
```

```bash
# Обновить существующую копию
cd New-mir
git pull origin main
pip install -r requirements.txt
python main.py
```

```bash
# Docker (рекомендуется)
docker compose up -d
# Веб-интерфейс: http://localhost:8000
```

```bash
# С русскоязычной моделью
NEW_MIR_CHAT_MODEL=sberbank-ai/rugpt3small python main.py

# С мультиязычной моделью (46 языков)
NEW_MIR_CHAT_MODEL=bigscience/bloom-560m python main.py
```
