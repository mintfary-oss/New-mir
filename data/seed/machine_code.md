# Машинный код, ассемблер и архитектура команд

## Что такое машинный код

Машинный код — это набор инструкций, которые процессор выполняет напрямую.
Каждая инструкция — это последовательность битов (0 и 1), кодирующая операцию
и операнды. Процессор не понимает Python, C++ или Rust — он понимает только
машинный код. Всё остальное компилируется или интерпретируется в него.

Пример: инструкция x86 ADD EAX, 1
В двоичном виде: 10000011 11000000 00000001
В шестнадцатеричном: 83 C0 01

## Системы счисления

### Двоичная (основание 2)
Каждый разряд — бит (0 или 1). Компьютер работает с двоичными числами на уровне
электрических сигналов: высокое напряжение = 1, низкое = 0.

Примеры:
- 0000 0001 = 1
- 0000 1010 = 10
- 1111 1111 = 255
- 1000 0000 = 128

Перевод из двоичного в десятичное:
1011 = 1×8 + 0×4 + 1×2 + 1×1 = 11

### Шестнадцатеричная (основание 16, hex)
Цифры: 0-9, A-F. Один hex-символ = 4 бита (ниббл).
Два hex-символа = 1 байт (8 бит).

Таблица:
0=0000, 1=0001, 2=0010, 3=0011
4=0100, 5=0101, 6=0110, 7=0111
8=1000, 9=1001, A=1010, B=1011
C=1100, D=1101, E=1110, F=1111

Примеры: 0xFF = 255, 0x0A = 10, 0xDEADBEEF = 3735928559

Зачем hex? Компактнее двоичного, легче читать адреса памяти:
0x7FFD4A2B — адрес в стеке, 0xC0000000 — начало ядра Linux

### Восьмеричная (основание 8)
Исторически использовалась в Unix для прав доступа:
chmod 755 → 7=111 (rwx), 5=101 (r-x), 5=101 (r-x)

## Биты, байты, слова

- 1 бит — минимальная единица информации (0 или 1)
- 1 ниббл = 4 бита
- 1 байт = 8 бит (значения 0–255)
- 1 слово (word) = 2 байта = 16 бит (исторически на x86)
- 1 двойное слово (dword) = 4 байта = 32 бит
- 1 четверное слово (qword) = 8 байт = 64 бит

Современный x86-64 работает с 64-битными регистрами (qword).

Диапазоны целых чисел:
- uint8:  0 до 255
- int8:  -128 до 127
- uint16: 0 до 65535
- int16: -32768 до 32767
- uint32: 0 до 4294967295 (~4 млрд)
- int32: -2147483648 до 2147483647
- uint64: 0 до 18446744073709551615 (~18 экзабайт)

## Дополнительный код (Two's complement)

Отрицательные числа хранятся в дополнительном коде.
Для числа -N: инвертировать все биты и прибавить 1.

Пример для 8-бит:
+5 = 0000 0101
-5 = 1111 1011 (инвертировали: 1111 1010, добавили 1: 1111 1011)

Преимущество: сложение работает одинаково для signed и unsigned.
5 + (-5) = 0000 0101 + 1111 1011 = 1 0000 0000 (перенос игнорируется) = 0 ✓

## Числа с плавающей точкой (IEEE 754)

### float32 (одинарная точность)
32 бита = 1 знак + 8 экспонента + 23 мантисса

Структура: S EEEEEEEE MMMMMMMMMMMMMMMMMMMMMMM

Число = (-1)^S × 2^(E-127) × 1.M

Примеры:
- 1.0 = 0 01111111 00000000000000000000000
- -2.0 = 1 10000000 00000000000000000000000
- 0.5 = 0 01111110 00000000000000000000000

Специальные значения:
- +∞: 0 11111111 00000000000000000000000
- NaN: X 11111111 ненулевая мантисса
- 0: все биты нулевые

### float64 (двойная точность)
64 бита = 1 знак + 11 экспонента + 52 мантисса
Диапазон: ~5×10^-324 до ~1.8×10^308

## Регистры процессора x86-64

Регистры — сверхбыстрые ячейки памяти внутри CPU.
Латентность: 0-1 такт (vs 4 такта L1-кэш, 10-40 L2, 100+ RAM).

### Регистры общего назначения (64-бит)
```
RAX — аккумулятор, возвращаемое значение функций
RBX — базовый регистр (сохраняемый)
RCX — счётчик циклов, 4-й аргумент (Linux)
RDX — данные, 3-й аргумент
RSI — источник (source index), 2-й аргумент
RDI — назначение (destination index), 1-й аргумент
RBP — указатель базы стека (base pointer)
RSP — указатель стека (stack pointer) — вершина стека
R8-R15 — дополнительные регистры (x86-64)
```

Псевдонимы (части одного регистра RAX):
```
RAX = 64-бит (весь регистр)
EAX = 32-бит (младшие 32 бита RAX)
AX  = 16-бит (младшие 16 бит)
AH  = 8-бит (биты 8-15)
AL  = 8-бит (биты 0-7)
```

### Специальные регистры
```
RIP — instruction pointer (счётчик команд), указывает на следующую инструкцию
RFLAGS — флаги результатов операций:
  CF (Carry Flag) — перенос при сложении
  ZF (Zero Flag)  — результат равен нулю
  SF (Sign Flag)  — результат отрицательный
  OF (Overflow)   — переполнение знакового числа
  PF (Parity)     — чётность младшего байта
```

### Регистры FPU/SSE/AVX
```
XMM0-XMM15 — 128-бит регистры (SSE/SSE2)
YMM0-YMM15 — 256-бит (AVX/AVX2), расширение XMM
ZMM0-ZMM31 — 512-бит (AVX-512)
```
Используются для векторных вычислений: SIMD (Single Instruction Multiple Data).
AVX2: одна инструкция обрабатывает 8 float32 одновременно.

## Архитектура команд x86-64

### Форматы инструкций
x86 — CISC архитектура. Инструкции переменной длины: 1-15 байт.

Структура (упрощённо):
[Префикс] [Опкод] [ModRM] [SIB] [Смещение] [Непосредственное]

Опкод — 1-3 байта, кодирует операцию.
ModRM — режим адресации (регистр, память, непосредственное).
SIB — Scale×Index+Base для сложных адресов памяти.

### Основные инструкции x86-64

Пересылка данных:
```asm
MOV rax, rbx        ; rax = rbx (копирование регистр→регистр)
MOV rax, [rbx]      ; rax = *rbx (загрузка из памяти)
MOV [rax], rbx      ; *rax = rbx (сохранение в память)
MOV rax, 42         ; rax = 42 (непосредственное значение)
MOVZX rax, al       ; rax = al (расширение нулями до 64 бит)
MOVSX rax, eax      ; rax = eax (расширение знаком)
LEA rax, [rbx+4]    ; rax = адрес (load effective address)
PUSH rax            ; rsp -= 8; [rsp] = rax
POP rax             ; rax = [rsp]; rsp += 8
XCHG rax, rbx       ; обмен значениями
```

Арифметика:
```asm
ADD rax, rbx        ; rax += rbx
SUB rax, rbx        ; rax -= rbx
MUL rbx             ; rdx:rax = rax * rbx (беззнаковое)
IMUL rax, rbx       ; rax *= rbx (знаковое)
DIV rbx             ; rax = rdx:rax / rbx; rdx = остаток
INC rax             ; rax++ (инкремент)
DEC rax             ; rax-- (декремент)
NEG rax             ; rax = -rax
ADC rax, rbx        ; rax += rbx + CF (с переносом)
SBB rax, rbx        ; rax -= rbx - CF (с заёмом)
```

Логические операции:
```asm
AND rax, rbx        ; rax &= rbx (побитовое И)
OR  rax, rbx        ; rax |= rbx (побитовое ИЛИ)
XOR rax, rbx        ; rax ^= rbx (исключающее ИЛИ)
NOT rax             ; rax = ~rax (побитовое НЕ)
XOR rax, rax        ; rax = 0 (быстрое обнуление)
TEST rax, rbx       ; AND без сохранения (устанавливает флаги)
CMP rax, rbx        ; SUB без сохранения (устанавливает флаги)
```

Сдвиги:
```asm
SHL rax, 1          ; rax <<= 1 (логический сдвиг влево, умножение на 2)
SHR rax, 1          ; rax >>= 1 (логический сдвиг вправо, деление на 2)
SAR rax, 1          ; арифметический сдвиг вправо (сохраняет знак)
ROL rax, 1          ; циклический сдвиг влево
ROR rax, 1          ; циклический сдвиг вправо
```

Управление потоком:
```asm
JMP label           ; безусловный переход
JE  label           ; jump if equal (ZF=1)
JNE label           ; jump if not equal (ZF=0)
JL  label           ; jump if less (SF≠OF, знаковое)
JG  label           ; jump if greater
JA  label           ; jump if above (CF=0, беззнаковое)
JB  label           ; jump if below (CF=1)
CALL func           ; push rip; jmp func
RET                 ; pop rip; (возврат из функции)
LOOP label          ; rcx--; if rcx≠0 jump label
```

Строковые операции:
```asm
MOVS  ; пересылка строки (REP MOVSB — memcpy)
CMPS  ; сравнение строк
SCAS  ; поиск в строке
STOS  ; заполнение (REP STOSB — memset)
LODS  ; загрузка строки в RAX
```

## Соглашения о вызовах (Calling Conventions)

### System V AMD64 ABI (Linux, macOS)
Аргументы в регистрах: RDI, RSI, RDX, RCX, R8, R9
Остальные аргументы — в стеке (справа налево).
Возвращаемое значение: RAX (целое/указатель), XMM0 (float).
Сохраняемые регистры (callee-saved): RBX, RBP, R12-R15.
Регистры можно испортить (caller-saved): RAX, RCX, RDX, RSI, RDI, R8-R11.

Пример: int add(int a, int b) { return a + b; }
```asm
add:
    mov eax, edi    ; eax = a (первый аргумент)
    add eax, esi    ; eax += b (второй аргумент)
    ret             ; возвращаем eax
```

### Windows x64 ABI
Аргументы: RCX, RDX, R8, R9
Shadow space: 32 байта резервируется в стеке перед вызовом.

## Стек и организация памяти процесса

### Стек (Stack)
Растёт от старших адресов к младшим (вниз).
RSP всегда указывает на вершину стека (последний записанный элемент).

```
Высокие адреса  +-------------------+
                | argv, environ      |
                +-------------------+
                |  Стек (stack)      | ← RSP (растёт вниз ↓)
                |       ↓            |
                +-------------------+
                |   (свободно)       |
                +-------------------+
                |       ↑            |
                |  Куча (heap)       | ← malloc/new
                +-------------------+
                |  BSS (zero-init)   |
                +-------------------+
                |  Data (init vars)  |
                +-------------------+
Низкие адреса   |  Text (код)        | ← RIP (указатель на код)
                +-------------------+
```

### Кадр стека (Stack Frame)
При вызове функции создаётся кадр стека:
```asm
push rbp          ; сохранить старый базовый указатель
mov rbp, rsp      ; установить новый базовый указатель
sub rsp, 32       ; выделить 32 байта под локальные переменные
...
mov rsp, rbp      ; восстановить указатель стека
pop rbp           ; восстановить базовый указатель
ret               ; вернуться
```

Кадр стека содержит:
- Локальные переменные функции
- Сохранённые регистры
- Адрес возврата
- Параметры (если не поместились в регистры)

## Режимы адресации x86

```
[reg]              ; прямая адресация через регистр: MOV rax, [rbx]
[reg + disp]       ; базовая + смещение: MOV rax, [rbx + 8]
[reg + reg*scale]  ; масштабирование: MOV rax, [rbx + rcx*4]
[base + idx*s + d] ; полная SIB форма: MOV rax, [rbx + rcx*4 + 16]
RIP-relative       ; относительно счётчика команд: MOV rax, [rip + offset]
```

Масштаб (scale) для индексирования массивов: 1, 2, 4, 8.
Например, для массива int32: arr[i] = [arr_base + i*4].

## Ассемблер NASM — синтаксис

```nasm
section .data
    msg db "Hello, World!", 10  ; строка с переносом
    len equ $ - msg             ; длина строки

section .bss
    buf resb 64                 ; 64 байта неинициализированного буфера

section .text
    global _start

_start:
    ; sys_write(1, msg, len)
    mov rax, 1          ; syscall: write
    mov rdi, 1          ; fd = stdout
    mov rsi, msg        ; буфер
    mov rdx, len        ; длина
    syscall

    ; sys_exit(0)
    mov rax, 60         ; syscall: exit
    xor rdi, rdi        ; код возврата 0
    syscall
```

## Системные вызовы Linux (syscalls)

Интерфейс между программой и ядром ОС.
Вызов: номер в RAX, аргументы в RDI, RSI, RDX, R10, R8, R9.
Инструкция: SYSCALL (или INT 0x80 в 32-бит режиме).

Основные syscalls x86-64:
```
0  read(fd, buf, count)
1  write(fd, buf, count)
2  open(filename, flags, mode)
3  close(fd)
9  mmap(addr, len, prot, flags, fd, off)
11 munmap(addr, len)
60 exit(code)
57 fork()
59 execve(filename, argv, envp)
39 getpid()
```

## ARM64 (AArch64) — мобильные и Apple Silicon

### Регистры ARM64
```
X0-X7   — аргументы функций и возвращаемые значения
X8      — косвенный адрес результата (large structs)
X9-X15  — временные (caller-saved)
X16-X17 — intra-procedure-call scratch (IP0, IP1)
X18     — зарезервирован (платформенный регистр)
X19-X28 — сохраняемые регистры (callee-saved)
X29     — frame pointer (FP)
X30     — link register (LR) — адрес возврата
SP      — stack pointer
PC      — program counter
```

W0-W30 — 32-битные псевдонимы X0-X30 (нижние 32 бита).

### Основные инструкции ARM64
```asm
MOV X0, #42         ; X0 = 42
ADD X0, X1, X2      ; X0 = X1 + X2
SUB X0, X1, X2      ; X0 = X1 - X2
MUL X0, X1, X2      ; X0 = X1 * X2
SDIV X0, X1, X2     ; X0 = X1 / X2 (знаковое)
AND X0, X1, X2      ; X0 = X1 & X2
ORR X0, X1, X2      ; X0 = X1 | X2
EOR X0, X1, X2      ; X0 = X1 ^ X2 (XOR)
LSL X0, X1, #2      ; X0 = X1 << 2
LSR X0, X1, #2      ; X0 = X1 >> 2 (логический)
ASR X0, X1, #2      ; X0 = X1 >> 2 (арифметический)
LDR X0, [X1]        ; X0 = *X1 (загрузка из памяти)
STR X0, [X1]        ; *X1 = X0 (сохранение в память)
LDP X0, X1, [SP]    ; загрузить пару регистров
STP X0, X1, [SP]    ; сохранить пару регистров
BL  func            ; branch with link (CALL)
RET                 ; возврат (через X30)
B   label           ; безусловный переход
B.EQ label          ; переход если равно
B.NE label          ; переход если не равно
```

ARM64 — RISC архитектура. Инструкции фиксированной длины 4 байта.
3 операнда: destination, source1, source2.

## Компиляция: от исходного кода до машинного кода

### Этапы компиляции (C/C++)

```
Исходный код (.c)
      ↓ Препроцессор (cpp)
Расширенный код (.i) — раскрыты #include, #define
      ↓ Компилятор (cc1)
Ассемблерный код (.s) — человекочитаемый asm
      ↓ Ассемблер (as)
Объектный файл (.o) — машинный код без адресов
      ↓ Компоновщик (ld)
Исполняемый файл (ELF/PE) — готовый к запуску
```

### Просмотр ассемблерного кода
```bash
gcc -O2 -S file.c -o file.s          # компилировать в asm
objdump -d -M intel binary            # дизассемблировать
objdump -d --no-show-raw-insn binary  # без байтов
readelf -a binary                     # информация об ELF
gdb binary → disassemble main         # в отладчике
```

### Пример: factorial в C и x86-64 ASM

C код:
```c
int factorial(int n) {
    if (n <= 1) return 1;
    return n * factorial(n - 1);
}
```

GCC -O2 генерирует (приблизительно):
```asm
factorial:
    cmp edi, 1          ; сравниваем n с 1
    jle .base_case      ; if n <= 1: goto base_case
    push rbx            ; сохраняем rbx (callee-saved)
    mov ebx, edi        ; ebx = n
    lea edi, [edi-1]    ; edi = n-1
    call factorial      ; rax = factorial(n-1)
    imul eax, ebx       ; rax = n * factorial(n-1)
    pop rbx
    ret
.base_case:
    mov eax, 1          ; return 1
    ret
```

## Форматы исполняемых файлов

### ELF (Executable and Linkable Format) — Linux/Unix
Структура ELF файла:
```
ELF Header (64 байта)
  magic: 7f 45 4c 46 ("ELF")
  class: 64-бит
  endian: little-endian
  machine: x86-64 (0x3E)
  entry point: адрес _start

Program Headers (сегменты для загрузчика)
  LOAD: .text (r-x) — код
  LOAD: .data (rw-) — данные
  DYNAMIC: таблица динамических зависимостей

Section Headers (секции для компоновщика)
  .text    — машинный код
  .rodata  — константы (read-only data)
  .data    — инициализированные глобальные переменные
  .bss     — неинициализированные глобальные переменные
  .symtab  — таблица символов
  .strtab  — таблица строк имён
  .plt     — Procedure Linkage Table (для dlopen)
  .got     — Global Offset Table
  .debug_* — отладочная информация (DWARF)
```

### PE (Portable Executable) — Windows
```
DOS Header + DOS Stub ("This program cannot be run in DOS mode")
PE Header
  signature: "PE\0\0"
  machine: AMD64 (0x8664)
  sections count, timestamp
Optional Header
  entry point RVA
  ImageBase (обычно 0x140000000 для 64-бит)
  stack/heap sizes
Sections:
  .text  — код
  .rdata — константы, импорты
  .data  — данные
  .rsrc  — ресурсы (иконки, строки)
  .reloc — таблица перемещений
```

## Оптимизации компилятора

### Уровни оптимизации GCC/Clang
```
-O0  — без оптимизации (отладочная сборка)
-O1  — базовые оптимизации
-O2  — рекомендуемый для продакшена
-O3  — агрессивные (может нарушить strict aliasing)
-Os  — оптимизация размера кода
-Oz  — минимальный размер (Clang)
-Og  — оптимизация с сохранением отладочности
```

### Что делает компилятор

Инлайнинг (inlining):
```c
// Исходный код:
inline int square(int x) { return x * x; }
int result = square(5);

// После инлайнинга — вызова нет:
int result = 25;  // или: imul result, 5, 5
```

Устранение хвостовой рекурсии (TCO):
```c
// Рекурсивный вызов в хвостовой позиции
int sum(int n, int acc) {
    if (n == 0) return acc;
    return sum(n-1, acc+n);  // хвостовая рекурсия
}
// Компилятор превращает в цикл без дополнительных кадров стека
```

SIMD-автовекторизация:
```c
// Цикл
for (int i = 0; i < 8; i++) c[i] = a[i] + b[i];
// Компилятор → одна инструкция AVX:
// VADDPS ymm0, ymm1, ymm2  (8 float32 за раз)
```

## Отладка и дизассемблирование

### GDB команды
```
gdb ./program
(gdb) break main          # точка останова
(gdb) run                 # запуск
(gdb) disassemble main    # дизассемблировать функцию
(gdb) info registers      # показать все регистры
(gdb) x/10xb $rsp         # 10 байт стека в hex
(gdb) x/5i $rip           # 5 инструкций от текущей
(gdb) stepi               # шаг по одной инструкции
(gdb) nexti               # следующая инструкция (без захода в call)
(gdb) print $rax          # значение регистра
(gdb) backtrace           # стек вызовов
```

```bash
hexdump -C binary | head  # hex + ASCII дамп
nm binary                 # символы (функции, переменные)
ldd binary                # зависимые библиотеки
strace ./program          # системные вызовы при выполнении
ltrace ./program          # вызовы библиотечных функций
perf stat ./program       # статистика производительности
```

## RISC-V — открытая архитектура

RISC-V — свободная ISA (Instruction Set Architecture) без лицензионных платежей.
Активно используется в встраиваемых системах, академических процессорах.

Базовый набор RV32I (32-бит):
```
32 регистра: x0 (всегда 0), x1 (ra), x2 (sp), x3 (gp)
             x4 (tp), x5-x7 (t0-t2), x8-x9 (s0-s1)
             x10-x17 (a0-a7 — аргументы), x18-x27 (s2-s11)
             x28-x31 (t3-t6)

Инструкции (все фиксированной длины 32 бита):
ADD rd, rs1, rs2     ; rd = rs1 + rs2
ADDI rd, rs1, imm    ; rd = rs1 + imm
LW rd, offset(rs1)   ; rd = *(rs1 + offset)  [load word]
SW rs2, offset(rs1)  ; *(rs1 + offset) = rs2 [store word]
BEQ rs1, rs2, label  ; if rs1==rs2 goto label
JAL rd, label        ; rd=pc+4; goto label   [jump and link]
JALR rd, rs1, imm    ; rd=pc+4; goto rs1+imm
ECALL                ; системный вызов
```

## Микрокод

x86 инструкции не всегда выполняются напрямую.
Сложные инструкции транслируются в простые микрооперации (µops).

Например, PUSHA (сохранение всех регистров) разбивается на ~8 µop.
Простые инструкции (MOV, ADD) = 1 µop.
Микрокод можно обновлять через microcode patches (фикс уязвимостей Spectre/Meltdown).

## Кэширование инструкций

Процессор кэширует часто используемые µops в µop cache (Decoded ICache).
Intel Skylake: µop cache хранит 1536 µop в 6 наборах по 6 путей.
Попадание в µop cache: пропуск этапов Fetch+Decode.

## Предсказание переходов (Branch Prediction)

Условные переходы (JE, JNE, ...) создают неопределённость:
куда пойдёт выполнение? Процессор предсказывает и выполняет спекулятивно.

Неверное предсказание → штраф 15-20 тактов на Skylake.
Верное предсказание → нулевой штраф.

Современные предсказатели (TAGE) достигают >99% точности на большинстве кода.

## Машинный код в Python

```python
import ctypes, mmap

# Выделяем исполняемую память
size = 4096
mem = mmap.mmap(-1, size, prot=mmap.PROT_READ|mmap.PROT_WRITE|mmap.PROT_EXEC)

# x86-64 машинный код: функция, возвращающая 42
# mov eax, 42; ret
code = bytes([0xB8, 0x2A, 0x00, 0x00, 0x00,  # MOV EAX, 42
              0xC3])                            # RET

mem.write(code)
mem.seek(0)

# Вызываем напрямую
addr = ctypes.addressof(ctypes.c_char.from_buffer(mem))
func = ctypes.CFUNCTYPE(ctypes.c_int)(addr)
result = func()  # result = 42
print(f"Результат: {result}")
```

## Важные концепции машинного кода

### Endianness (порядок байт)
Little-endian (x86): младший байт по меньшему адресу.
0x12345678 → байты в памяти: 78 56 34 12

Big-endian (сети, некоторые ARM): старший байт первый.
0x12345678 → байты в памяти: 12 34 56 78

Network byte order = big-endian. htons(), htonl() для конвертации.

### Выравнивание (Alignment)
Данные должны быть выровнены по своему размеру для быстрого доступа:
- int32 по адресу, кратному 4
- int64 по адресу, кратному 8
- SIMD 128-бит: выравнивание по 16 байт

Невыравненный доступ работает (x86), но медленнее (~3% штраф на L1-кэш промахах).

### Volatile и барьеры памяти
```c
volatile int flag = 0;  // компилятор не оптимизирует доступ
```

Memory barriers (fence): гарантируют порядок операций с памятью.
```asm
MFENCE  ; полный барьер памяти
LFENCE  ; барьер загрузок
SFENCE  ; барьер сохранений
```

Нужны для многопоточного кода: без барьеров CPU может переупорядочить операции.
